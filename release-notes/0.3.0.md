Async Batcher 0.3.0 adds bounded streaming, callable processors, compatible request groups,
and new database and messaging adapters. It also fixes cancellation, shutdown, result routing,
and resource ownership across the core and existing adapters. The core retains zero runtime
dependencies; install backend clients only through the extras you need.

```bash
python -m pip install 'async-batcher==0.3.0'
```

Read the [0.3.0 documentation](https://hussein.awala.fr/async-batcher/0.3.0/) and
[migration guide](https://hussein.awala.fr/async-batcher/0.3.0/migration/) before upgrading from 0.2.2.

## Significant changes and upgrade notes

- **Python 3.11 or newer is required; Python 3.10 support is removed.** Optional SDK requirements
  are refreshed, including SQLAlchemy 2.0.10+ and Keras 3.15.1+. Keras 2 is no longer supported;
  install and validate a compatible backend separately. [#90](https://github.com/hussein-awala/async-batcher/pull/90),
  [#91](https://github.com/hussein-awala/async-batcher/pull/91)
- **Invalid configuration and processor results fail explicitly.** Unknown constructor options,
  invalid numeric limits, and unordered, unsized, or incorrectly sized result collections are
  rejected. `max_batch_size=1` is now supported. Process and interpreter pool executors are
  rejected because they cannot share the batcher's event-loop state. The existing limit defaults
  remain unchanged; replace the retained `batch_size` alias with `max_batch_size`.
  [#103](https://github.com/hussein-awala/async-batcher/pull/103),
  [#106](https://github.com/hussein-awala/async-batcher/pull/106)
- **Shutdown waits for accepted work and cleanup.** Keep clients and executors alive through
  shutdown. A timeout leaves graceful cleanup running; await it again or request forced shutdown.
  A fully stopped core batcher can restart on its original loop. Cancelling a caller does not
  guarantee that its accepted external write was prevented.
  [#49](https://github.com/hussein-awala/async-batcher/pull/49),
  [#78](https://github.com/hussein-awala/async-batcher/pull/78),
  [#110](https://github.com/hussein-awala/async-batcher/pull/110)
- **Review adapter assumptions.** SQLAlchemy bulk updates require mapped ORM models and primary
  keys; Core `Table` updates and UPDATE RETURNING are rejected. DynamoDB enables TLS by default,
  enforces service batch-count limits, and retries unprocessed requests with bounded backoff.
  Recheck application retry policies and corrected per-item result behavior during migration.
  [#54](https://github.com/hussein-awala/async-batcher/pull/54),
  [#56](https://github.com/hussein-awala/async-batcher/pull/56),
  [#58](https://github.com/hussein-awala/async-batcher/pull/58),
  [#62](https://github.com/hussein-awala/async-batcher/pull/62),
  [#72](https://github.com/hussein-awala/async-batcher/pull/72)

## Features

- Wrap an existing async or synchronous bulk function with `AsyncBatcher.from_callable` and use
  async context managers for cleanup. [#124](https://github.com/hussein-awala/async-batcher/pull/124)
- Process sync or async sources with bounded `map` and `map_outcomes`; choose input or completion
  order and retain indexed per-item outcomes. Admission can wait for queue capacity with its own
  timeout. [#127](https://github.com/hussein-awala/async-batcher/pull/127),
  [#136](https://github.com/hussein-awala/async-batcher/pull/136)
- Limit batch cost as well as item count, using application estimates such as bytes or tokens.
  [#125](https://github.com/hussein-awala/async-batcher/pull/125)
- Group compatible requests with bounded child ownership and aggregate capacity; coalesce
  equivalent in-flight requests without caching completed results.
  [#129](https://github.com/hussein-awala/async-batcher/pull/129),
  [#137](https://github.com/hussein-awala/async-batcher/pull/137),
  [#140](https://github.com/hussein-awala/async-batcher/pull/140),
  [#144](https://github.com/hussein-awala/async-batcher/pull/144)
- Flush accepted work without closing intake, including child-accepted work in grouped batchers.
  Opt into discarding cancelled requests before dispatch when that fits the operation.
  [#147](https://github.com/hussein-awala/async-batcher/pull/147),
  [#149](https://github.com/hussein-awala/async-batcher/pull/149),
  [#177](https://github.com/hussein-awala/async-batcher/pull/177)
- Inspect immutable statistics and payload-free batch events, configure processor context, and
  optionally omit exception details from library logs. Ship installed-package type information
  with `py.typed`. [#128](https://github.com/hussein-awala/async-batcher/pull/128),
  [#131](https://github.com/hussein-awala/async-batcher/pull/131),
  [#134](https://github.com/hussein-awala/async-batcher/pull/134),
  [#138](https://github.com/hussein-awala/async-batcher/pull/138),
  [#143](https://github.com/hussein-awala/async-batcher/pull/143)
- Add native Kafka producer batches, ordered MongoDB writes, Pinecone vector operations, and
  Kinesis/Firehose record batches. DynamoDB reads gain strong consistency and validated projections.
  [#97](https://github.com/hussein-awala/async-batcher/pull/97),
  [#107](https://github.com/hussein-awala/async-batcher/pull/107),
  [#112](https://github.com/hussein-awala/async-batcher/pull/112),
  [#113](https://github.com/hussein-awala/async-batcher/pull/113),
  [#114](https://github.com/hussein-awala/async-batcher/pull/114),
  [#115](https://github.com/hussein-awala/async-batcher/pull/115)

## Fixes

- Prevent duplicate or stranded dispatchers, preserve batch peers when one caller is cancelled,
  respect the oldest queued item's collection deadline, reject self-shutdown, and propagate
  `StopIteration` without hanging requests. Startup failures no longer leave requests queued for
  unintended later execution. [#65](https://github.com/hussein-awala/async-batcher/pull/65),
  [#73](https://github.com/hussein-awala/async-batcher/pull/73),
  [#75](https://github.com/hussein-awala/async-batcher/pull/75),
  [#95](https://github.com/hussein-awala/async-batcher/pull/95),
  [#99](https://github.com/hussein-awala/async-batcher/pull/99),
  [#167](https://github.com/hussein-awala/async-batcher/pull/167)
- Correct DynamoDB duplicate-key correlation, missing results, key validation, empty batches,
  and unsupported write operations. [#59](https://github.com/hussein-awala/async-batcher/pull/59),
  [#64](https://github.com/hussein-awala/async-batcher/pull/64),
  [#67](https://github.com/hussein-awala/async-batcher/pull/67),
  [#92](https://github.com/hussein-awala/async-batcher/pull/92)
- Release SQLAlchemy sessions, preserve INSERT RETURNING order and heterogeneous parameter
  dictionaries, and honor Scylla model connections and counter-batch rules.
  [#55](https://github.com/hussein-awala/async-batcher/pull/55),
  [#58](https://github.com/hussein-awala/async-batcher/pull/58),
  [#93](https://github.com/hussein-awala/async-batcher/pull/93),
  [#98](https://github.com/hussein-awala/async-batcher/pull/98),
  [#105](https://github.com/hussein-awala/async-batcher/pull/105)
- Combine Keras samples into a dense batch, preserve structured prediction results, and keep
  scikit-learn sparse inputs and predictions sparse. Both prediction adapters expose bounded
  queues and forward core options. [#69](https://github.com/hussein-awala/async-batcher/pull/69),
  [#87](https://github.com/hussein-awala/async-batcher/pull/87),
  [#109](https://github.com/hussein-awala/async-batcher/pull/109),
  [#133](https://github.com/hussein-awala/async-batcher/pull/133)
- Remove raw request debug logging and correct example server/client shutdown ordering.
  [#76](https://github.com/hussein-awala/async-batcher/pull/76),
  [#81](https://github.com/hussein-awala/async-batcher/pull/81),
  [#85](https://github.com/hussein-awala/async-batcher/pull/85)
